# ESP32仕様（β版）

ここでは、Obserleaf（β版）におけるESP32の仕様についてまとめている。


## 1. 概要

β版では、センサー値の取得とサーバへの送信をESP32が担当する。

ESP32は、接続された各センサーから植物の生育環境に関するデータを取得し、JSON形式に変換してWi-Fi経由でRaspberry Pi 5上のDjango APIへ送信する。また、計測間隔や各センサーの有効・無効といったデバイス設定をRaspberry Pi 5から取得し、自身の動作に反映する。

本書ではESP32側のハードウェア構成、ソフトウェア構成、処理フロー、センサー仕様設定仕様および通信仕様を対象とする。受信データの検証・変換・保存などRaspberry Pi 5側の処理については「データフロー（β版）」を、APIごとのデータ項目の詳細については同書の「3. データ項目」を参照すること。


## 2. 動作環境

| 項目 | 内容 |
| --- | --- |
| ボード | ESP32（esp32dev） |
| 開発環境 | PlatformIO |
| フレームワーク | Arduino |
| プログラミング言語 | Arduino系C/C++ |
| シリアル通信速度 | 115200 bps |
| 使用ライブラリ | DHT sensor library、Adafruit Unified Sensor、ArduinoJson |
| 温湿度センサー | DHT22 |
| 土壌水分センサー | Capacitive Soil Moisture Sensor v1.2 |
| 照度センサー | LM393を使用した照度センサー |
| 通信方式 | Wi-Fi、HTTP |
| 送信先 | Raspberry Pi 5（Django API） |

ファームウェアのビルドおよび書き込みには、あらかじめ `config.h.example` を `config.h` にコピーし、利用する環境に合わせて設定値を書き換えておく必要がある（「7.1 ローカル設定」を参照）。


## 3. ハードウェア構成

### 3.1 ピン配置

センサーおよびLEDの接続先GPIOは、`pin_config.h` で一括して管理する。

| 接続先 | GPIO | 入出力 | 備考 |
| --- | --- | --- | --- |
| DHT22（データ） | 4 | 入力 | 温湿度センサー |
| 土壌水分センサー（アナログ出力） | 34 | 入力 | ADC値を取得する |
| 照度センサー（アナログ出力） | 35 | 入力 | ADC値を取得する |
| LED（温湿度） | 13 | 出力 | 緑色 |
| LED（土壌水分） | 14 | 出力 | 青色 |
| LED（光量） | 16 | 出力 | 黄色 |

LEDの役割については「9. 状態表示・ログ仕様」を参照すること。


## 4. ソフトウェア構成

ESP32のプログラムは、`esp32-sensor/src/` 配下で役割ごとにモジュール分割されている。

| モジュール | 主なファイル | 役割 |
| --- | --- | --- |
| メイン処理 | main.cpp | システム全体の制御（初期化、計測タイミングの管理、計測・送信の実行） |
| 設定（固定値） | config/config.h、config/pin_config.h | デバイス識別名、ファームウェアバージョン、Wi-Fi情報、APIのURL、ピン配置などの固定値を管理する |
| データモデル | models/sensor_data.h | 計測データを保持する構造体（SensorData）を定義する |
| センサー | sensors/dht_sensor、sensors/soil_sensor、sensors/light_sensor | 各センサーの初期化と値の取得、有効判定を行う |
| ネットワーク | network/wifi-manager、network/api_client | Wi-Fi接続、計測データの送信、デバイス設定の取得、適用済み設定の報告を行う |
| ユーティリティ | utils/config_manager | Raspberry Piから取得したデバイス設定の保持と、設定変更の判定を行う |
| ユーティリティ | utils/time_manager | NTPによる時刻同期と現在時刻の取得を行う |
| ユーティリティ | utils/led_indicator | センサーの状態に応じたLED表示を行う |
| ユーティリティ | utils/logger | シリアルモニタへのログ出力を行う |

### 4.1 計測データ構造（SensorData）

各モジュール間で計測データをやり取りするための構造体であり、以下の項目を持つ。

| 項目 | 内容 | データ型 |
| --- | --- | --- |
| timestamp | 計測時刻（Unix時刻、秒） | uint32_t |
| temperature | 温度（℃） | float |
| humidity | 湿度（%） | float |
| soilRaw | 土壌水分センサーの生データ（ADC値） | int |
| lightRaw | 光センサーの生データ（ADC値） | int |
| dhtEnabled / soilEnabled / lightEnabled | 各センサーの計測有効状態 | bool |
| dhtValid / soilValid / lightValid | 各センサーの計測結果が有効かどうか | bool |


## 5. 処理フロー

### 5.1 起動処理

電源投入時は、以下の順序で初期化を行う。

1. シリアル通信を初期化する（115200 bps）
2. LEDを初期化し、起動確認として全LEDを3回点滅させる
3. 設定管理を初期化する（初期設定は「7.2 サーバーから配布される設定」を参照）
4. すべてのセンサーを初期化する（後から設定で有効化できるよう、無効なセンサーも含めて初期化する）
5. Wi-Fiに接続する
6. NTPで時刻を同期する
7. Raspberry Piから最新のデバイス設定を取得し、計測間隔へ反映する
8. センサーデータを1回取得し、送信する

### 5.2 主処理

起動後は、以下の処理を繰り返す。

| 処理 | タイミング | 内容 |
| --- | --- | --- |
| 設定確認 | 10秒ごと | Raspberry Piからデバイス設定を取得し、設定が変更された場合のみ反映する。反映した場合は、その場でセンサーデータを1回取得・送信する |
| 計測・送信 | 計測間隔ごと | センサーデータを取得し、Raspberry Piへ送信する |
| LED更新 | 常時 | センサーのエラー状態と計測タイミングに応じてLED表示を更新する |

### 5.3 計測・送信処理

1. 現在適用されているデバイス設定をもとに、有効なセンサーのみを読み取る
2. 計測時刻として、現在時刻（Unix時刻、秒）を設定する
3. センサーごとに計測結果の有効判定を行い、エラー状態を記録する
4. 計測結果をシリアルモニタへログ出力する
5. 計測データをJSON形式に変換し、Raspberry Piへ送信する


## 6. センサー仕様

### 6.1 共通事項

- 各センサーは、デバイス設定によって計測の有効・無効を切り替えられる。無効なセンサーは読み取らない。
- 計測結果にはセンサーごとに有効判定（Valid）があり、無効と判定された計測値は送信データに `null` を設定する（「データフロー（β版）」の「3. データ項目」を参照）。
- ESP32は土壌水分率や光量スコアへの変換を行わない。土壌水分センサーと光センサーについては生データ（ADC値）をそのまま送信し、変換はRaspberry Pi側で行う。

### 6.2 温湿度センサー（DHT22）

| 項目 | 内容 |
| --- | --- |
| 取得値 | 温度（℃）、湿度（%） |
| 取得方法 | DHTライブラリによるデジタル読み取り |
| 有効判定 | 温度・湿度のいずれかがNaNの場合は無効とする |

### 6.3 土壌水分センサー

| 項目 | 内容 |
| --- | --- |
| 取得値 | ADC値（生データ） |
| 取得方法 | analogReadによるアナログ読み取り |
| 有効判定 | ADC値が0以下、または4095以上の場合は無効とする |

### 6.4 照度センサー（LM393）

| 項目 | 内容 |
| --- | --- |
| 取得値 | ADC値（生データ） |
| 取得方法 | analogReadによるアナログ読み取り |
| 有効判定 | ADC値が0以下、または4095以上の場合は無効とする |


## 7. 設定仕様

ESP32の設定には、ファームウェアに保持するローカル設定と、Raspberry Piから配布される設定の2種類がある。

### 7.1 ローカル設定（config.h）

| 設定項目 | 内容 |
| --- | --- |
| DEVICE_NAME | デバイスの識別名 |
| FIRMWARE_VERSION | ファームウェアのバージョン |
| SENSOR_DHT_ENABLED / SENSOR_SOIL_ENABLED / SENSOR_LIGHT_ENABLED | 起動時の各センサーの有効・無効（サーバー配布設定の初期値としても使用する） |
| WIFI_LIST | 接続先Wi-FiのSSIDとパスワードのリスト（複数登録可） |
| API_URL | 計測データ送信用APIのURL |
| DEVICE_CONFIG_API_URL | デバイス設定取得用APIのURL |
| DEVICE_CONFIG_APPLIED_API_URL | 適用済み設定報告用APIのURL |

`config.h` は `config.h.example` をコピーして作成する。Wi-Fiのパスワードなどの実際の値はリポジトリに含めない。

### 7.2 サーバーから配布される設定（DeviceConfig）

| 設定項目 | 内容 | 初期値 |
| --- | --- | --- |
| configVersion | 設定のバージョン | 0 |
| intervalSeconds | 計測間隔（秒） | 5 |
| dhtEnabled | 温湿度センサーの有効状態 | ローカル設定の値 |
| soilEnabled | 土壌水分センサーの有効状態 | ローカル設定の値 |
| lightEnabled | 光センサーの有効状態 | ローカル設定の値 |

設定の取得と反映は、以下のルールで行う。

- 起動時に1回取得し、その後は10秒ごとに変更を確認する。
- 取得した設定の `configVersion` が、現在適用しているバージョンより新しい場合にのみ反映する。同じバージョン、または古いバージョンの場合は反映しない。
- 取得に失敗した場合は、現在の設定を維持する。
- 設定を反映した場合は、適用したバージョンをRaspberry Piへ報告する。報告できなかったバージョンは、未報告として保持される。
- 反映後の計測間隔は `intervalSeconds` をミリ秒に変換したものを使用する。


## 8. 通信仕様

### 8.1 Wi-Fi接続

- 起動時に、`WIFI_LIST` に登録された順序で接続を試みる。
- 1つの接続先に対する試行は、500ミリ秒間隔で最大20回（約10秒）までとする。
- 接続に成功した場合は、そのSSIDとIPアドレスをシリアルモニタへ出力して処理を進める。
- すべての接続先に失敗した場合は、その旨を出力する。この場合、時刻同期やデータ送信は行えない（「10. 異常時動作」を参照）。

### 8.2 API通信

ESP32が関わるAPIは以下の3つであり、各APIのデータ項目の詳細は「データフロー（β版）」の「3. データ項目」にまとめる。

| API | メソッド / エンドポイント | 向き | タイミング |
| --- | --- | --- | --- |
| 計測データ受信API | POST `/api/receive` | ESP32 → Raspberry Pi | 計測のたび |
| デバイス設定取得API | GET `/api/device_config/` | ESP32 → Raspberry Pi | 起動時、10秒ごとの設定確認時 |
| 適用済み設定報告API | POST `/api/device_config/applied/` | ESP32 → Raspberry Pi | 設定の変更を適用したとき |

計測データ送信の応答として返される `next_interval` は、受信してログに記録するが、計測間隔の決定には使用しない。計測間隔はデバイス設定取得APIで取得した `intervalSeconds` によって決まる。


## 9. 時刻仕様

| 項目 | 内容 |
| --- | --- |
| 同期方式 | NTP |
| NTPサーバー | pool.ntp.org |
| タイムゾーン | 日本時間（UTC+9、夏時間なし） |
| 同期タイミング | 起動時（Wi-Fi接続後） |
| 同期の待ち時間 | 最大15秒（500ミリ秒間隔で最大30回確認） |
| 計測時刻 | 同期した時刻に基づくUnix時刻（秒）を `timestamp` として送信する |

※ 日付が変わった際の再同期を行う関数（`updateTimeSync()`）は定義されているが、現在の主処理からは呼び出されていない。


## 10. 状態表示・ログ仕様

### 10.1 LED表示

LEDはセンサーごとに割り当てられており、状態を以下のように表示する。

| 表示 | 意味 |
| --- | --- |
| 起動時に全LEDが3回点滅 | 起動確認 |
| 計測直後に100ミリ秒間点灯 | 計測が行われたこと（ハートビート） |
| 該当センサーのLEDが点灯したままになる | そのセンサーの計測がエラーであること |

割り当ては、温湿度が緑色（GPIO 13）、土壌水分が青色（GPIO 14）、光量が黄色（GPIO 16）である。

### 10.2 シリアルログ

シリアルモニタ（115200 bps）には、動作確認とデバッグのために以下のログを出力する。

| ログ | 内容 |
| --- | --- |
| SYSTEM ALERT | センサーごとの異常（読み取り失敗、異常値）の通知 |
| TIME | 計測時刻 |
| SENSOR DATA | 計測値の一覧（無効なセンサーは DISABLED、エラー時はその旨を表示） |
| HTTP REQUEST / HTTP RESULT | 送信したJSON、HTTPステータスコード、処理結果と次回間隔 |
| [CONFIG] | デバイス設定の取得結果、変更の有無、適用と報告の結果 |
| [TIME] | NTP同期の成否と同期した時刻 |
| [HTTP] | Wi-Fi未接続など、送信を行えない場合の理由 |


## 11. 異常時動作

| 現象 | 検出方法 | 動作 |
| --- | --- | --- |
| センサーの読み取り失敗・異常値 | センサーごとの有効判定 | エラー状態として記録し、該当センサーのLEDを点灯させる。送信データではその計測値を `null` とし、他のセンサーの計測と送信は継続する |
| Wi-Fi未接続時の送信 | Wi-Fi接続状態の確認 | 送信を行わず、失敗としてログに記録する。再送やデータの保持は行わない |
| 起動時にWi-Fiへ接続できない | 登録されたすべての接続先で失敗 | その旨をログに記録する。時刻同期は行われず、以降の送信も行えない |
| NTP同期の失敗 | 同期の待ち時間を超過 | 失敗をログに記録し、処理を継続する |
| デバイス設定の取得失敗 | HTTPエラー、応答の形式不正など | 現在の設定を維持し、次回の確認タイミングで再度取得を試みる |
| 計測データの送信失敗 | HTTPステータスが200番台でない | 失敗としてログに記録する。再送は行わない |


## 12. 設計意図

### 12.1 センサー取得をESP32へ分離したこと

Raspberry PiはWebアプリケーションやデータ管理を担当し、ESP32はセンサー値の取得と送信に専念することで、役割を分離した。また、ESP32を複数台運用できる構成とし、複数の植物を同時に観測できるようにしている。

### 12.2 設定をサーバーから配布する方式にしたこと

計測間隔やセンサーの有効・無効をRaspberry Pi側で管理し、ESP32が定期的に取得・反映する方式とした。これにより、ファームウェアを書き換えることなく、稼働中のESP32の動作を変更できる。

### 12.3 生データを送信すること

土壌水分と光量については、ESP32は生データ（ADC値）を送信し、土壌水分率や光量スコアへの変換をRaspberry Pi側に集約した。これにより、変換の基準値を変更する場合も、ファームウェアの書き換えが不要になる。
