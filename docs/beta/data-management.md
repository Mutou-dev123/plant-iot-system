# データ管理方針（β版）

ここでは、ObserLeaf（β版）のデータ保存期間、グラフ表示、日別集計、育成植物とセンサーログの紐づけ、およびデータ保守・バックアップ方針についてまとめています。


## 1. データ保存方針

### 1.1 センサーログ（SensorLog）

センサーログは、短期間の環境変化を確認するための生データとして保存する。

- 保存期間：365日
- 保存期間を過ぎたログは、自動削除の対象とする。
- 日別集計が正常に完了したことを確認してから削除する。
- 日別集計に失敗した場合は、対象の生ログを削除しない。

### 1.2 日別集計データ（DailySensorSummary）

日別集計データは、長期的な環境変化の分析に利用するため、センサーログとは別に保存する。

- 保存期間：5年
- 保存期間を過ぎたデータは、自動削除する。
- 生ログの削除後も、日別集計データは保持する。


## 2. グラフ表示方針

### 2.1 表示期間

グラフの表示期間を選択できるようにし、短期間から長期間までの環境変化を確認できる構成とする。

### 2.2 表示項目

以下の測定項目をそれぞれ確認できるようにする。

- 気温
- 湿度
- 土壌水分
- 光量スコア

日別集計データが存在しない期間は、存在するデータのみを表示する。データが存在しない期間をゼロで補完しない。


## 3. 日別集計方針

### 3.1 集計対象

新たに DailySensorSummary モデルを作成し、センサーログを日単位で集計する。

集計単位は、デバイスID・育成植物ID・集計日の組み合わせとする。

### 3.2 集計項目

各測定項目について、平均値・最大値・最小値を保存する。

| 測定項目 | 保存する集計値 |
|---|---|
| 気温 | 平均値・最大値・最小値 |
| 湿度 | 平均値・最大値・最小値 |
| 土壌水分 | 平均値・最大値・最小値 |
| 光量スコア | 平均値・最大値・最小値 |

また、集計対象となったログ件数、作成日時、更新日時を記録する。

### 3.3 集計データの制約

- デバイスID・育成植物ID・集計日の組み合わせに一意制約を設定する。
- 欠損値はゼロとして扱わず、欠損として扱う。
- 集計処理を再実行しても、同じ集計対象のデータが重複して作成されない構成とする。


## 4. 育成植物とセンサーログの紐づけ

### 4.1 DeviceとPlantの関連付け

Device.plantは、デバイスに設定されている現在の観測対象植物として維持する。

デバイス管理画面から管理対象の植物を変更できる仕様も維持する。

### 4.2 SensorLogへのPlantの追加

SensorLogにplant外部キーを追加し、各計測データがどの育成植物に対応するかを記録する。

新しいセンサーログの保存時には、保存時点での植物との対応関係を記録する。

日別集計では、Device.plantの現在値ではなく、保存済みのSensorLog.plantを基に植物別に集計する。

### 4.3 既存ログの取り扱い

既存のセンサーログについては、過去の設定履歴を確認して植物IDを対応付ける。

正確な履歴を復元できない場合は、推測で植物IDを割り当てない。

植物の変更時刻と測定時刻のずれ、およびデバイス削除時の履歴保存については、実装時に取り扱いを決定する。


## 5. 自動処理・データ保守

### 5.1 日別集計処理

日付が変わった後、前日のセンサーログを対象として日別集計を自動実行する。

集計処理の成功・失敗や処理件数を記録し、失敗した場合は対象の生ログを削除しない。

### 5.2 センサーログの自動削除

日別集計が正常に完了したことを確認したうえで、保存期間を過ぎたセンサーログを自動削除する。

集計処理と削除処理を連携させることで、集計前の生データが失われることを防ぐ。

### 5.3 日別集計データの自動削除

保存期間が5年を超えた日別集計データを自動削除する。

自動処理の実行結果や処理件数を記録し、処理状況を確認できるようにする。

### 5.4 データベース容量の管理

SQLiteのデータベースファイルサイズを監視する。

データ削除後もデータベースファイルのサイズが自動的に小さくなるとは限らないため、必要に応じて容量メンテナンスを実施する。


## 6. バックアップ

データの保全性を高めるため、今後の実装でバックアップ機能の導入を検討する。

現時点では、バックアップの実行方式や保存先などの詳細は未確定とし、以下の項目を今後の検討対象とする。

- Raspberry Pi本体やSDカードとは別の保存先へのバックアップ
- バックアップの実行頻度と保存世代数
- バックアップの実行日時や成功・失敗の記録
- バックアップ失敗時の通知・再実行方法
- バックアップデータの復元手順と定期的な復元テスト

具体的な実装方式は、利用可能な保存先や運用条件を確認した後に決定する。


## 7. SDカードの容量監視

### 7.1 容量情報の表示

Web画面から、ストレージの使用状況を確認できるようにする。

| 表示項目 | 内容 |
|---|---|
| 総容量 | SDカードの総容量 |
| 使用容量 | 使用中の容量 |
| 空き容量 | 利用可能な容量 |
| 使用率 | 総容量に対する仕様容量の割合 |
| データベースサイズ | SQLiteのデータベースファイルサイズ |
| 自動管理処理の実行結果 | 集計・削除などの最終実行結果 |

### 7.2 容量不足の警告

ストレージの使用率に応じて警告を表示する機能を実装する。

使用率80％・90％を初期案とし、実際の運用状況に応じて警告閾値を調整する。
